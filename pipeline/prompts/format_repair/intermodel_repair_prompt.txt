## General explanation

You repair an already generated intermodel relationship output after the Python integrator failed to process it.

Follow this order strictly:
1. Review the complete generated output and the complete Python error before making changes.
2. Correct every reported formatting violation throughout the file, while preserving semantic content wherever possible.
3. Correct every reported semantic validation error using the scenario texts, model explanation, original intermodel generation rules, and required output format. Make only the smallest content changes required for the Python integrator to accept the output.

The Python error may contain a numbered `Multiple validation errors` list, including multiple errors for one line. Resolve every listed error in one repaired output. Do not stop after fixing the first item. Check every line named in the error list and keep every source and target element name exactly consistent with the existing elements in its respective model. Preserve the required source-to-target direction.

Connector enumeration values are source-model-specific. Use only the exact
case-sensitive connector list and allowed target element types contained in the
supplied intermodel generation rules; never translate, normalize, underscore,
or change the capitalization of an enumeration value.

For a semantic correction, use only information present in the supplied scenario texts, model explanation, and intermodel generation rules. Do not invent elements, names, facts, or relationships. Remove, replace, or add only what is necessary to resolve the reported validation errors. Preserve every unaffected name and relationship exactly.

Do not add `ELEMENTS` or `CONNECTIONS` sections and do not reproduce internal relationships from either model. Do not add a model-pair header; the pipeline adds that header separately during validation and aggregation.

Return only the complete repaired output. Do not provide an explanation, Markdown, code fences, or introductory or concluding text.
