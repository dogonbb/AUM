Create intermodel relationships between two existing 4EM models.

## Purpose

Intermodel relationships connect elements from different 4EM models.

They express meaningful dependencies, responsibilities, activities, definitions, or other semantic relationships between elements that were created in separate models but describe the same enterprise case.

The purpose of this task is not to modify the two models. The purpose is only to identify meaningful relationships between their existing elements.

## How the models were generated

The two models have already been generated independently from the same enterprise case description.

Each model was created using a separate 4EM-specific generation prompt. Each generation prompt:

- defined the purpose of the respective model;
- restricted the model to its allowed element types;
- defined the meanings of those element types;
- restricted the model to its allowed internal connection types;
- required all elements to be grounded in the provided case description;
- prohibited unsupported or invented elements;
- required a structured output containing an ELEMENTS section and a CONNECTIONS section;
- required connections to use element names without including their element types.

As a result, the two models may describe related parts of the same enterprise case, even though they were generated independently.

Do not create new model elements.
Do not rename existing model elements.
Do not modify or reproduce the internal connections of either model.

## Task

Identify all semantically meaningful intermodel relationships from elements of the source model to elements of the target model.

Consider every element of the source model as a possible source. As targets, use
only elements whose element type is listed as allowed for the target model below.

However, create a relationship only when it is supported by the meanings of the two elements and by the provided case descriptions.

Do not create a relationship merely because the two elements contain similar words.
Do not create speculative relationships that are not supported by the available information.
Do not create relationships between two elements belonging to the same model.

## Direction

Every returned relationship must start with an element from the source model and end with an element from the target model.

Do not reverse the direction.

## Output format

Return only the intermodel relationships.

Write exactly one relationship per line using the following syntax:

<ElementNameFromModel1> <Connector> <ElementNameFromModel2>

Use only the exact element names declared in the `ELEMENTS` sections of the
source model and target model shown above.

Do not include the element type before or after an element name.

Do not prefix either element name with its element type. For example, if an
element is declared as `Role Customer Service Representative`, use only
`Customer Service Representative` as its name in a relationship line.

## Output rules

1. Return relationships only.
2. Do not return an ELEMENTS section.
3. Do not return a CONNECTIONS heading.
4. Do not reproduce internal model relationships.
5. Do not create new elements.
6. Do not rename, shorten, translate, or normalize element names.
7. Do not include element types in the relationships.
8. Use only the allowed connectors.
9. Do not include explanations, comments, bullet points, numbering, Markdown, or code fences.
10. Create at most one relationship between any pair of elements. Do not connect the same source and target elements more than once, even with different connectors. Choose the single most specific applicable connector.
11. If no meaningful intermodel relationship can be identified, return exactly:

NO_INTERMODEL_RELATIONSHIPS
