Create a Goal Model according to 4EM for the given case.

## Purpose of the model

The Goal Model describes what the enterprise and its employees want to achieve or avoid, and when.
It shows goals together with problems that hinder their achievement.
It also explains why processes, rules, requirements, and other enterprise model elements exist or do not exist.

## Allowed element types

Use only the following element types:

- Goal
- Problem
- Cause
- Constraint
- Opportunity

Do not use any other element types.
Do not create elements such as Product, Service, Component, Feature, Actor, Role, Resource, Concept, Technical Component, Requirement, Process, Market, or Business Rule.

## Allowed direct connection types

Use only the following direct connection types:

- supports
- hinders
- contradicts
- causes

## Allowed connector types

Use only the following connector-based connections:

- AND
- OR
- AND/OR

## Meaning of element types

- Goal: a desired state, aim, need, requirement, vision, direction, or measurable business objective.
- Problem: an undesirable current or possible future state that hinders goals. Threats and weaknesses are modeled as Problem.
- Cause: a reason or situation that causes a Problem or Opportunity.
- Constraint: an external restriction, rule, law, policy, or fixed limitation.
- Opportunity: a favorable situation that the enterprise may want to take advantage of.

## Meaning of direct connections

Use direct connections only for simple one-to-one relations.

- A supports B  
  means that A helps, contributes to, enables, or positively influences B.

- A hinders B  
  means that A obstructs, prevents, weakens, or negatively influences B.

- A contradicts B  
  means that A is in conflict with B.

- A causes B  
  means that A produces, leads to, or explains B.

## Meaning of connector-based connections

Use connector-based connections when multiple elements are connected by one AND, OR, or AND/OR connector.

- A, B, C AND D  
  means that A, B, and C are connected to D by an AND connector.

- A, B, C OR D  
  means that A, B, and C are connected to D by an OR connector.

- A, B, C AND/OR D  
  means that A, B, and C are connected to D by an AND/OR connector.

## Allowed connection patterns

For supports:

- Goal supports Goal
- Opportunity supports Goal

For hinders:

- Goal hinders Goal
- Problem hinders Goal
- Constraint hinders Goal

For contradicts:

- Goal contradicts Goal

For causes:

- Cause causes Problem
- Cause causes Opportunity

For AND, OR, and AND/OR connectors:

- Goal, Problem, and Opportunity may be connected with Goal, Problem, and Opportunity.

## Modeling rules

1. Use Goal for desired states, objectives, needs, requirements, visions, or directions.
2. Use Problem for undesirable states, threats, or weaknesses that hinder goals.
3. Use Cause only for reasons that cause a Problem or Opportunity.
4. Use Constraint only for external restrictions, rules, laws, policies, or fixed limitations.
5. Use Opportunity only for favorable situations that can be exploited.
6. If a statement contains both a problem and an opportunity, split it into two elements.
7. Use supports only when the source element positively contributes to the target goal.
8. Use hinders only when the source element negatively affects the target goal.
9. Use contradicts only for a real conflict between two goals.
10. Use causes only from Cause to Problem or from Cause to Opportunity.
11. Use connector-based connections when the case describes grouped or decomposed elements.
12. Every element used in CONNECTIONS must be listed exactly once in ELEMENTS.
13. Do not invent elements that are not supported by the case text.
14. Do not write explanations, comments, descriptions, bullet points, or any text outside the required output sections.

## Output format

Output the model only in the following format:

ELEMENTS
ElementType <name_1>
ElementType <name_2>
ElementType <name_3>
...

CONNECTIONS
<element name> supports <element name>
<element name> hinders <element name>
<element name> contradicts <element name>
<element name> causes <element name>
<element name_1>, <element name_2>, <element name_3> AND <element name>
<element name_1>, <element name_2>, <element name_3> OR <element name>
<element name_1>, <element name_2>, <element name_3> AND/OR <element name>



Note that for connections, you shouldn’t include the ElementType in the Connection.
