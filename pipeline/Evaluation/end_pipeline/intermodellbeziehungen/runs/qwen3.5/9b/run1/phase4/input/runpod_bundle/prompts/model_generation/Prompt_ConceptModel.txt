Create a Concepts Model according to 4EM for the given case.

## Purpose of the model

The Concepts Model defines the "things" and "phenomena" one is talking about in the other models.
It more strictly defines expressions in the Goal Model as well as the content of resources in the Business Processes Model.
It describes the business language used in the enterprise and shows how concepts are related.

## Allowed element types

Use only the following element types:

- Concept
- Attribute

Do not use any other element types.
Do not create elements such as Goal, Problem, Cause, Constraint, Opportunity, Product, Service, Component, Feature, Actor, Role, Resource, Technical Component, Requirement, Process, Market, or Business Rule.

## Allowed direct connection types

Use only the following direct connection types:

- 1:1
- 1:n
- n:m
- has attribute

## Allowed connector types

Use only the following connector-based connections:

- Partial-ISA
- Total-ISA
- Partial-PartOF
- Total-PartOF

## Meaning of element types

- Concept: something in the domain of interest and application that the enterprise wants to reason about, characterize, and define using relationships to other entities.
- Attribute: a concept that is used only to characterize a Concept. It is a property of the type of objects referenced by the characterized Concept.

## Meaning of direct connections

Use direct connections only for simple one-to-one relations.

- A 1:1 B  
  means that one instance of Concept A is related to exactly one instance of Concept B, and one instance of Concept B is related to exactly one instance of Concept A.

- A 1:n B  
  means that one instance of Concept A may be related to several instances of Concept B.

- A n:m B  
  means that several instances of Concept A may be related to several instances of Concept B.

- A has attribute B  
  means that Concept A is characterized by Attribute B.

## Meaning of connector-based connections

Use connector-based connections when one or more elements are connected by one Partial-ISA, Total-ISA, Partial-PartOF, or Total-PartOF connector. A connector with exactly one source and one target is valid.

- A, B, C Partial-ISA D  
  means that A, B, and C are specific concepts or attributes connected to the more generic concept or attribute D by a partial ISA connector.

- A, B, C Total-ISA D  
  means that A, B, and C are specific concepts or attributes connected to the more generic concept or attribute D by a total ISA connector.

- A, B, C Partial-PartOF D  
  means that A, B, and C are parts connected to the aggregate concept or attribute D by a partial PartOF connector.

- A, B, C Total-PartOF D  
  means that A, B, and C are parts connected to the aggregate concept or attribute D by a total PartOF connector.

## Allowed connection patterns

For 1:1:

- Concept 1:1 Concept

For 1:n:

- Concept 1:n Concept

For n:m:

- Concept n:m Concept

For has attribute:

- Concept has attribute Attribute

For Partial-ISA, Total-ISA, Partial-PartOF, and Total-PartOF connectors:

- Concept and Attribute may be connected with Concept and Attribute.

## Modeling rules

1. Use Concept for things and phenomena in the domain of interest and application.
2. Use Concept for terms that the enterprise talks about and that need to be defined.
3. Use Concept for business objects, information objects, domain objects, or important terms from the case text.
4. Use Attribute only for properties that characterize a Concept.
5. Do not model an Attribute as an independent Concept if it is used only to characterize another Concept.
6. Use has attribute only when the source Concept is characterized by the target Attribute.
7. Use 1:1 only when the case text supports a one-to-one relation between two Concepts.
8. Use 1:n only when the case text supports a one-to-many relation between two Concepts.
9. Use n:m only when the case text supports a many-to-many relation between two Concepts.
10. Use Partial-ISA or Total-ISA only for generalisation or specialisation relations.
11. Use Partial-PartOF or Total-PartOF only for aggregation or part-of relations.
12. Use connector-based connections when the case describes grouped, decomposed, generalized, specialized, or aggregated elements.
13. Every element used in CONNECTIONS must be listed exactly once in ELEMENTS.
14. Do not invent elements that are not supported by the case text.
15. Do not write explanations, comments, descriptions, bullet points, or any text outside the required output sections.
16. An element must never be both a source and the target of the same connection. In particular, do not repeat the connector target in the source list of Partial-ISA, Total-ISA, Partial-PartOF, or Total-PartOF.

## Output format

Output the model only in the following format:

ELEMENTS
ElementType <name_1>
ElementType <name_2>
ElementType <name_3>
...

CONNECTIONS
<element name> 1:1 <element name>
<element name> 1:n <element name>
<element name> n:m <element name>
<element name> has attribute <element name>
<element name_1>, <element name_2>, <element name_3> Partial-ISA <element name>
<element name_1>, <element name_2>, <element name_3> Total-ISA <element name>
<element name_1>, <element name_2>, <element name_3> Partial-PartOF <element name>
<element name_1>, <element name_2>, <element name_3> Total-PartOF <element name>


Note that for connections, you shouldn’t include the ElementType in the Connection.
